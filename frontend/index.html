      How it works
      
        
      
          
      Debugging rarely fails because there's no information — it fails because the information is scattered. ReproLens takes five artifacts from an ML experiment and correlates them, rather than asking a model to summarize each one in isolation.
      
          
      1. Deterministic checks run first
      
          
      Before Bedrock ever sees the evidence, rule-based checks compare facts directly — for example, the class count in your config against the class count in your dataset metadata. These are verified facts, not AI guesses.
      
          
      2. Bedrock investigates the relationships
      
          
      Amazon Bedrock, using strict tool use, receives the deterministic findings plus the full evidence bundle and returns a structured diagnosis — every claim citing a specific artifact and field.
      
          
      3. You verify it yourself
      
          
      Every evidence node in the graph is clickable and opens the exact source line. Competing hypotheses are shown, not hidden. When the evidence genuinely isn't enough, ReproLens says so instead of guessing.

      Bedrock is the reasoning engine, not decoration — every diagnosis is a schema-constrained tool call, validated locally against the same JSON Schema used to build the request. DynamoDB history writes are deliberately kept off the critical path: a history failure never blocks a diagnosis response.
      
        
      
      
      

      
      
      
        
      About
      
        
      
          
      ReproLens was built for First Commit (AWS × WeMakeDevs, Bharat Builds Tour), Ship It track.
      
          
      Honestly stated limitations: validated against 6 synthetic fixtures, not real-world data. Scoped to PyTorch-shaped config/log conventions. No authentication — this demo has no login because none exists yet, not because it was hidden.
